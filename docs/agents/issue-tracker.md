# Issue tracker: GitHub Issues

Active work is tracked in GitHub Issues for this repository. Local `.scratch/` folders retain specs, research, and other working artifacts; they are not the source of truth for issue status.

## Conventions

- One GitHub Issue per independently actionable task.
- Link each issue to its supporting spec or decision record in `.scratch/` or `docs/`.
- Use the triage labels in `triage-labels.md` and add relevant type or area labels when useful.
- Record discussion and decisions in the issue conversation. Close the issue when its acceptance criteria are complete.
- Use GitHub task lists and issue links for dependencies; do not create duplicate local ticket files.

## When a skill says "publish to the issue tracker"

Create a GitHub Issue in this repository, with a concise problem statement, acceptance criteria, and relevant labels.

## When a skill says "fetch the relevant ticket"

Read the referenced GitHub Issue and its comments. The user will normally pass an issue number or URL.
